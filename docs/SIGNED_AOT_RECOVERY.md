# Whole-game signed AOT recovery

This is a product prerequisite, not an optional device optimization. See `10-code-packaging-and-signing.md`. Since 2026-09-24 all 518 code modules are signed and `OTTSEL_STRICT_EXEC` makes any runtime code loading fatal ([evidence](evidence/G1/g1-all-code-signed-strict-2026-09-24.md)); the notes below record how the loader got there.

## Existing foothold and limits
`out/jak-project/tools/ottsel_a1_1/a11_slice_emitter.cpp` compiles an embedded kernel subset, separates text/data and emits Mach-O assembler references. It does not yet support arbitrary compiled objects. The recovery validator now rejects unsupported symbols/types, pointer/distance64 records, malformed bounds and unsupported instruction pairs before emitting assembly/maps.
`src/shell/a11_slice_runner.mm` uses fixed x22=0x100000000, while full gameplay uses a separate `g_ee_main_mem` mapping. Its real generated name= symbol/string branches now call a signed static symbol->string shim through the production GOAL/C bridge and a writable target slot. The runner checks pointer bounds, text immutability and VM permissions. Never register native pointers through an unchecked u32 cast.
`out/jak-project/tools/ottsel_h2/h2_static_shim.s` demonstrates signed text reading writable slots. Use this existing ABI approach; do not create another engine.
