## Next steps (renderer core, smallest falsifiable first)

The DMA chain structure is decoded (see the s22 evidence doc): the first
CALL -> the default-registers chain at 0x506310 (a CNT tag, 10 qwords of GIF
data at 0x506320, then RET); the NEXT tags -> the bucket draw lists.  The
GIF data at 0x506320 starts with a GifTag {nloop=1, eop=1, flg=IMAGE,
nreg=2} followed by the A+D register values (DIMX/ALPHA_1/ZBUF_1/TEST_1/
PABE/TEXA/FOGCOL/TEXCLUT...).

1. `send_chain`: implement the DmaFollower walk (the runtime's own
   common/dma/dma_chain_read.h) + GifTag parse (common/dma/gs.h).  Route
   the GIF IMAGE payloads into a VRAM array using
   common/texture/texture_conversion.h (psmct32_addr/psmt8_addr).  Verify:
   the VRAM bytes for the first chain match the GS IMAGE data.
2. `texture_upload_now`: decode the tpage texture with the CORRECT CLUT
   region (the GoalTexture clutpsm/dest fields).  The texels are NOT in the
   tpage's segment[0].block_data (that region holds pointers/descriptions);
   they arrive via the chain IMAGE payloads.  Reuse the converter's
   download_rgba8888 logic (the tpage probes log the ids: 0x1cf, 0x2,
   0x370 (64x64 PSMT8), 0x4fe, ...).
3. Then rasterize the direct/background draws (the title background quad)
   from the bucket draw data; the title backdrop (tpage-1609, uploaded at
   the title screen) is the expected first correct visible frame.
4. Full-FPS + touch (S3) + package (R1) remain.
