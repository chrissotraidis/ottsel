## What was just proven (BOT10, this session)

The STR RPC emulation is now **semantically wired and its response value
controls the GOAL path**.  Three builds, three distinct behaviors, all on the
same boot (one Simulator, Windowed, zero stale processes):

| Emulated STR response | Observed behavior |
|---|---|
| `DONE, maxlen=requested` | `Game subtitle heap overrun!` spin (365k) — overrun guard `(>= load-status (+ heap-free -300))` trips because requested == full heap free |
| `ERROR` | `Error loading subtitle` spin (1.49M) — `str-load-status` returns 'error, loader prints and returns 0, caller retries |
| `DONE, maxlen=0` | **No spin.** GAME.CGO links (346 objects), emulation fires exactly once, boot advances to `(link new-mem name 0 heap 0)` |

The `DONE + maxlen=0` boot is a **new milestone**: it is the first time the
boot advanced past the subtitle/text loader.  The **new, distinct fault** is a
runtime-linker assert:

```
[die] Assertion failed: 'false'
  klink.cpp:77  link_control::jak1_jak2_begin(Ptr<uint8_t>, const char*, int32_t, Ptr<kheapinfo>, uint32_t)
```

That assert is the `VERSION ERROR` check — the zero-length text buffer has no
GOAL object header (goal_version_major 0 != 1), so the linker refuses it.
Evidence: `docs/evidence/S2/s21-strfix-done0-linkassert-runtime.log` (fault at
log line 2880), `s21-strfix-done0-linkassert-fault.log` (empty — assert aborts
before the fault handler).
