# BOT12 goal-based loop - drive Ottsel to "running and playing at full FPS"

Date: 2026-08-11.  Supersedes `2026-08-11-bot11-handoff.md` for *active*
work; that document remains the record of the BOT10/11 fixes.

## The fixed goal (do not shrink it)

Get the native Jak 1 port (Ottsel) **actually running and playing at full
FPS** on the iPad Pro 11-inch (M4) Simulator, ROM-safe, proof-gated, with the
worktree deliberately dirty (no commits/pushes unless the operator asks).
"Running and playing" = a boot that reaches the game's normal render loop and
produces real, visible, interactive frames (S2.2 then S3).  "Full FPS" = the
render loop sustains the game's native 60 Hz frame budget on the M4
Simulator, verified by frame counters/log evidence, not just one frame.

Completed and CLOSED (do not reopen without contradictory evidence): H1, H2,

## Loop mechanics (binding)

1. **One booted Simulator, one runtime, Windowed only.**  Before any
   relaunch: `pgrep -fl OttselShell` and SIGKILL the stale PID (the fault
   handler ignores SIGTERM).  UDID `08636791-2675-4675-8335-EF72EF954DCF`.
2. **One reproducible gate at a time.**  Change the smallest falsifiable
   thing, rebuild, boot ONCE (expect 1-4 relaunches for the
   non-deterministic link-phase fault class - that is a known fault, not a
   new blocker), read the bundle logs, and only then decide the next probe.
3. **Proof discipline.**  Every claim is checked against the running app,
   `ottsel-runtime.log` / `ottsel-fault.log` (via
   `xcrun simctl get_app_container $UDID com.ottsel.shell app`), and
   compiled-kernel ground truth.  `lg::info` reaches the log; `printf` may
   not.  Evidence goes in `docs/evidence/S2/` as `s21-bot12-*`.
4. **Docs update only after a verified milestone:** `docs/STATUS.md`,
   `docs/13-current-state.md`, `docs/00-loop-log.md`, and a handoff/loop doc
   in `docs/reports/`.  Correct stale claims when they are disproven.
5. **Honest stop:** if the same blocker repeats for 3 consecutive boots with
   no new information, stop, write the honest report (verified / unverified /
   externally blocked), and do not claim progress.
6. **Never:** patch game source (`*.gc`) to mask runtime bugs; commit or
   push without the operator asking; add ROMs/ISOs/assets/scratch to git;
   fullscreen the app.

## Current verified state (BOT11/12, 2026-08-11)

Fixed and verified this week: STR RPC emulation (`DONE,maxlen=0`), size-0
linker guard (klink.cpp), `g_ottsel_str_rpc_bd`/`g_ottsel_dgo_rpc_bd` init,
case-insensitive DGO filename resolution + `read_binary_file` try/catch
(sif_ee.cpp), **`init_crc()` in the iOS shell** (unblocked the whole
game-init path: `_empty_` interning was broken), and **the missing `(play)`
boot step** in `src/shell/ios_boot.cpp` (native boots call it from
`InitMachineScheme` when `DiskBoot`; iOS never did).

The boot now: KERNEL.CGO (8) -> GAME.CGO (346 objects) -> `(play
:use-vis :init-game)` -> ART.CGO (served from the bundle `iso_data` copy) ->
TIT.DGO (title-vis links) -> COMMON.CGO objects correctly skipped (original
PS2 objects already inside recompiled GAME.CGO) -> game-info init passes ->
process tree populated -> **the title screen state is entered
("GAMEPLAY: enter title") and the game runs its title loop** -> faults when
the target enters its first state.

**Next fault (deterministic):** `enter-state` (gstate.o) calls the target's
first state (`(go target-continue ...)` at the end of init-target) and the
state object is **all zeros** -- `intern_from_c("target-continue")`'s value
is 0x42b4000, which is shrub-work's static-data region, not target-death's
(0x4624000).  The no-emit linker's static-reference/static-data patching is
placing the state at the wrong address (same class as the earlier
constant-pool anomaly).  Evidence:
`docs/evidence/S2/s21-bot12-title-enter-*`.

## Fixed this loop (BOT12, all in the worktree, uncommitted)

1. `src/shell/ios_boot.cpp`: low-EE guard PROT_NONE -> PROT_READ (zeroed):
   the PS2 has no MMU; game code legitimately reads low memory through
   default-initialized pointers (vector<-cspace! null-bone read; the
   swamp-blimp w==0 guard).  Reads now benign; writes/execute still fault.
2. `out/jak-project/goalc/emitter/IGenARM64.cpp` `msub_gpr32`: MSUB base
   missing the "o" bit -> emitted MADD; `(mod a b)` was a + (a/b)*b
   (update-wind index fault).  Fixed + clang-verified (0x1B01C400).
3. Same file `min_vf`/`max_vf`: FAMIN/FAMAX (ARMv9.2) -> FMIN/FMAX
   (ARMv8), M4 SIGILL fixed (bones.gc pc 0x42308c8).

## Known unknowns / honest risk list

- The OpenGOAL renderer has never run on iOS.  S2.0 proved the Metal
  pipeline presents a CPU surface (verified pixel-for-pixel); wiring the
  game's render output into that path (and the GPU-side work that implies)
  is the largest remaining unknown and the majority of the honest estimate
  of remaining work.
- Full-FPS performance is unproven (frame pacing, backbuffer/swap, shader
  cost on the M4 Simulator).
- Touch input (S3) and app lifecycle are entirely unbuilt.
- Physical-device/signing/ROM licensing boundaries stay outside this loop;
  this loop targets the Simulator only.
