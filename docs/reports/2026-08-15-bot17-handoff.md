## Gotchas (this loop)

- REGLIST XYZF2 register = 64 bits; the observed values pack x in the low 16
  (0x7000..0x9000 = fullscreen width) with a constant 0x7910 field; the
  DirectRenderer2 math maps 0x8000->center, /0x1000 per NDC unit.
- VIF UNPACK_V4_32 = 0x6c in the tag's high byte; tfrag batches repeat a
  10-qword constant block, then big vertex batches (floats), 16-bit frag
  values, and NaN (0x7fc00000) terminators.
- Link-phase faults remain nondeterministic (~1-in-3); relaunch until the
  fault log is 0 bytes; the app holds at fault for lldb.

### Implementation notes for the jak1 v3-PS2 link path (BOT21i)

Reference: `decompiler/ObjectFile/LinkedObjectFileCreation.cpp` link_v3()
and the LinkHeaderV3 struct.  Layout (all little-endian):

```
struct LinkHeaderV3 {          // 128 bytes
  u32 type_tag;                // 0
  u32 length;                  // link-data length (village1-part: 0x6f0)
  u32 version;                 // 3
  u32 segments;                // 3
  char name[64];
  struct { u32 relocs, data, size, magic; } segment_info[3];  // magic=0
};
```

- Segment i data starts at `length + segment_info[i].data` (aligned 16;
  the last segment ends at the object size).
- Segment i reloc table at `segment_info[i].relocs` (byte offset from the
  object start).  Encoding: seek/fix variable-length integer run table --
  `count = byte`; seeking: advance the code ptr by `4*count`; fixing:
  `count` consecutive pointer words at the code ptr; `0xff` ends the run
  (a following 0 switches mode); a 0 byte ends the table.  The pointer
  word's value is the link:
  - `(value >> 24) == 0`: internal word pointer, dest offset = `value`
    (same segment).
  - else: split pointer: `dest_seg = (value >> 8) & 0xf`,
    `lo_hi = (value >> 12) & 0xf` (position of the low word),
    `offset = (low_word & 0xffff) + ((value & 0xff) << 16)`.
- The runtime fix: the pointer word's final value = dest segment's EE base
  + the resolved offset (the exact unit -- byte vs word -- must be checked
  against a known v3 part during implementation; the decompiler resolves
  offsets into the segment's word list).
- Placement: the v3 parts are mostly data; put the segments in the DGO
  double-buffer (the object the GOAL side already copied), fix the
  internal pointers, and do NOT run a top-level (data-only).  The serve
  rule (game/sce/sif_ee.cpp) must accept the v3 tag=0x0 blocks for the
  level DGOs (not for ART.CGO's "texture-upload" data record).
- Success check: after the village1 load, `(-> *level* level0 bsp)` is
  nonzero and the tfrag tree has >1 fragment with real LOD data.
