Date: 2026-08-15.  Read `docs/evidence/S2/s22-bot16-texture-decode.md` and
`docs/evidence/S2/s22-bot16-tfrag-vu1-boundary.md` first.

## Objective (unchanged)

S2.1 (verified) -> S2.2 first real Jak frame via Metal -> S3 touch -> R1
package.  One Simulator, one runtime, Windowed only.

## Verified / committed

- S2.1: title boot stable (3d15997).  S2.2 texture decode verified
  (aeaca3d): real game textures present through Metal, zero faults.
- This loop (uncommitted at handoff time): the renderer-core draw decoder +
  a direct-bucket rasterizer (OttselRaster: 512x448, GS->screen transform,
  barycentric tris, fake-VRAM texture sampling, alpha/scissor/xy-offset),
  wired and running with zero faults; tfrag/sprite VIF dump probes.
- Analysis (evidence `s22-bot16-tfrag-vu1-boundary.md`): the composed title
  frame CANNOT come from the direct bucket -- the title scene and sprites are
  produced by the game's VU1 microprograms (tfrag-vu1-block, sprite-vu1-block;
  the runtime does not emulate VU1).  The direct bucket's REGLIST quads are
  degenerate (x 0x7000..0x9000, y=0x7910 constant; draws=0 in the rasterizer).

## Next step (the actual blocker): VU1 emulation for tfrag

1. Port/emulate the tfrag VU1 microprogram.  Sources in-checkout:
   `test/decompiler/vu_reference/tfrag.txt` (raw) + `tfrag-result.txt`
   (disassembled); the DMA builder is emulated in
   `game/mips2c/jak1_functions/tfrag.cpp`; the GOAL init layouts in
   `goal_src/jak1/engine/gfx/tfrag/` (14-qword tfrag-data, 4-qword camera
   matrices).  A minimal VU1 interpreter (ADD/MUL/MADD/SUB/LQ/SQ/FCOND/branch
   + the GIF packet emitter) is the core piece.
2. Then the sprite VU1 (2D sprites/fonts) and the merc/tie VU1s.
3. Then the direct rasterizer (already written) handles the output GIF
   packets; the framebuffer copies (tbp 0x2800/0x3000, 512x256) then have
   real content.

## Gotchas (this loop)

- REGLIST XYZF2 register = 64 bits; the observed values pack x in the low 16
  (0x7000..0x9000 = fullscreen width) with a constant 0x7910 field; the
  DirectRenderer2 math maps 0x8000->center, /0x1000 per NDC unit.
- VIF UNPACK_V4_32 = 0x6c in the tag's high byte; tfrag batches repeat a
  10-qword constant block, then big vertex batches (floats), 16-bit frag
  values, and NaN (0x7fc00000) terminators.
- Link-phase faults remain nondeterministic (~1-in-3); relaunch until the
  fault log is 0 bytes; the app holds at fault for lldb.
