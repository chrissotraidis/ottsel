## Verified / committed

- S2.1: title boot stable (3d15997).  S2.2 texture decode verified
  (aeaca3d): real game textures present through Metal, zero faults.
- This loop (uncommitted at handoff time): the renderer-core draw decoder +

  degenerate (x 0x7000..0x9000, y=0x7910 constant; draws=0 in the rasterizer).

## Next step (the actual blocker): VU1 emulation for tfrag

1. Port/emulate the tfrag VU1 microprogram.  Sources in-checkout:
   `test/decompiler/vu_reference/tfrag.txt` (raw) + `tfrag-result.txt`
   (disassembled); the DMA builder is emulated in
   `game/mips2c/jak1_functions/tfrag.cpp`; the GOAL init layouts in
   `goal_src/jak1/engine/gfx/tfrag/` (14-qword tfrag-data, 4-qword camera
   matrices).  A minimal VU1 interpreter (ADD/MUL/MADD/SUB/LQ/SQ/FCOND/branch
   + the GIF packet emitter) is the core piece.
2. Then the sprite VU1 (2D sprites/fonts) and the merc/tie VU1s.
3. Then the direct rasterizer (already written) handles the output GIF
   packets; the framebuffer copies (tbp 0x2800/0x3000, 512x256) then have
   real content.

## Gotchas (this loop)

- REGLIST XYZF2 register = 64 bits; the observed values pack x in the low 16
  (0x7000..0x9000 = fullscreen width) with a constant 0x7910 field; the
  DirectRenderer2 math maps 0x8000->center, /0x1000 per NDC unit.
- VIF UNPACK_V4_32 = 0x6c in the tag's high byte; tfrag batches repeat a
  10-qword constant block, then big vertex batches (floats), 16-bit frag
  values, and NaN (0x7fc00000) terminators.
- Link-phase faults remain nondeterministic (~1-in-3); relaunch until the
  fault log is 0 bytes; the app holds at fault for lldb.

## Update (BOT18c, same day) — VIF semantics resolved

- UNPACK dest = (imm bit15 ? TOPS : 0) + (imm & 0x3ff): all observed imms
  are absolute (5/0x14d/0x290/0x160/0x381/0x384/0x3d4; 82k-record scan).
- MSCALF imm=0 -> VU starts at pc 0 -> jump table -> `b L11` -> strip path
  (vi14 = 0x2a0).  Traced.
- OPEN: the frag list at 0x2a0 is never written by any VIF unpack.  Next:
  find who writes 0x2a0 (tfrag-work scratchpad path / boot-time write), then
  run the microcode to XGKICK, capture the GIF, rasterize.

## Update (BOT18e, same day) — definitive VIF-chain findings

3994-record captures confirm: the tfrag draws use only V4-32 unpacks at the
7 absolute dests; the V4-8 color path never fires in the boot; the small
DIRECT transfers are uninitialized DMA gaps.  The vertex math fits
dest = base + imm (vertex list at 0x400), but the frag-list header at
vi14 = 0x2a0 is NOT written by any captured transfer.  Next probe:
instrument the interpreter's VU reads to map the expected layout, and/or
trace the game's tfrag-work scratchpad handoff for the boot-time write.

## Update (BOT19, same day) — two fixes verified; stable full-vis village boot

Read `docs/evidence/S2/s22-bot19-village-load-stable.md` first.

FIXED (both falsifiable, verified against the running app):

1. **TIT.DGO build regression** (`scripts/build-ios.sh`): the BOT18
   full-data commit's retail DGO loop overwrote the recompiled TIT.DGO, so
   `title-obs` (defines `target-title`) was skipped and `(go target-title)`
   faulted at EE+0.  The loop now skips TIT.DGO and the recompiled
   `out/jak1/iso/TIT.DGO` is copied last.  Bundle md5 verified = 3e47f065.
2. **goalc ARM64 emitter** (`goalc/emitter/IGenARM64.cpp` `mov_vf_vf`):
   the MOV idiom ORR Vd,Vn,Vn left Rm=0 -> every 128-bit reg copy OR-ed with
   the stale return register V0.  Root cause of the entity-nav-login ->
   engine-new allocation explosion (garbage length 0xce6e6b28001920b4 ->
   object-new returns 0 -> SIGBUS at EE+6).  One-line fix (Rm = src);
   regression case 23 in `tools/ottsel_a1/semantic_regressions.cpp` fails
   before (word 0x4ea01c28 rm=0 rn=1) and passes after.  KERNEL.CGO /
   GAME.CGO / TIT.DGO recompiled with the fixed goalc (full obj-cache
   rebuild; GAME.CGO now has 159 ORR-mov words Rm==Rn).

VERIFIED (one boot, one Simulator, Windowed): `ottsel-fault.log` = 0 bytes;

`village1-vis` (7,479,408 bytes, result=DONE); 6 texture frames presented

## Update (BOT19e, same day) — VU1 interpreter wired; frag-list decode is the blocker

The VU1 interpreter is now compiled into the shell (`tools/ottsel_vu1/vu1.cpp`
+ `src/shell/tfrag_microcode.h` with the 1867 tfrag words) and `gfx_send_chain`
processes the live VIF stream (TOP/TOPS/STCYCL tracked, UNPACK -> VU data mem,

gif_out = 0 -- the frag list (count@TOP+0.hi16 etc.) is empty at runtime and

draws.  The next step is the game's tfrag-work / draw-inline-array-tfrag
frag-list construction (CPU-side draw state), not the VIF/UNPACK path (that
part is now emulated and validated).

## Update (BOT19f, same day) — tfrag geometry audit: LOD vertices empty, pages real

Live symbol-table ground truth corrects the earlier probe: `*tfrag-work*` IS
valid (value field at slot+0 = 0x042cc000; the TFRAGWORK probe read slot+4).
But the tfrag-work draw-state fields are all zero (src-ptr/last-call/
dma-buffer/vis-bits), and the per-draw DMA data shows the far-LOD vertex
batch (0x160) is EMPTY geometry (the S2.1 `(0,0,0,-1792)` marker) while the
page batch (0x3d4) has the real 16-bit village mesh and the frag batch
(0x384) has real frag positions.  `*vu1-enable-user*` = 0x1bfff8 (enabled).
The composed frame needs the game's frag-list/page construction (the mips2c
draw-inline-array-tfrag writes the per-draw unpacks but never the frag-list
header at VU words 0-4, and the LOD vertices stay empty).  All the emulation
pieces (VIF -> VU mem -> VU1 -> XGKICK -> rasterizer) are wired and
validated; the remaining work is the game-side geometry build.

## Update (BOT19g, same day) — draw-inline-array-tfrag (mips2c) never runs

A probe in `draw_inline_array_tfrag::execute` (the mips2c table[0x200] entry
behind the 0x4f10994 stub) never fires across a 3-minute stable boot while
the tfrag DMA chains flow.  The compiled draw-drawable-tree-tfrag does not
call the mips2c draw; the per-draw UNPACKs come from the compiled path, which
never writes the frag-list header (VU words 0-4) and leaves the far-LOD
vertex batch (0x160) empty.  The real village mesh is in the page batch
(0x3d4) consumed only by the near (L6/L7) microcode path.  The S2.2 frame
needs either the far-LOD vertex data populated (level/tfrag login) or the
near path with a valid frag-list.  App-side VIF/VU1/XGKICK/raster emulation
is complete and validated.
